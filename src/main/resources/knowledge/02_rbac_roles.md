# RBAC权限体系

## 角色定义

系统定义四种核心角色，存储于role表的code字段，角色判断不区分大小写。

### ADMIN - 系统管理员

拥有所有系统权限，可管理所有资产和用户。

### LEADER - 部门领导

可审批报废申请，查看部门报表，管理部门资产。

### MANAGER - 资产管理员

管理本部门资产，处理申请，执行盘点，计算折旧。

### USER - 普通用户

发起资产申请，查看个人资产，查看资产信息。

## 角色枚举

系统还定义了扩展角色：

- ASSET_MANAGER - 部门资产管理员
- DEPT_MANAGER - 部门管理员

这两个角色在权限判断时等同于MANAGER角色。

## 权限范围

### ADMIN权限

- 用户管理：增删改查所有用户
- 角色管理：增删改查所有角色
- 部门管理：增删改查所有部门
- 资产管理：增删改查所有资产，更新所有资产状态
- 申请管理：审批所有申请
- 盘点管理：创建和管理所有盘点计划
- 折旧管理：计算所有资产折旧
- 采购管理：管理所有采购订单
- 报表查看：查看所有报表
- 日志查看：查看所有操作日志

### LEADER权限

- 用户管理：查看本部门用户
- 资产管理：查看本部门资产，查看资产详细信息
- 申请管理：审批本部门报废申请（终审）
- 盘点管理：查看本部门盘点计划
- 折旧管理：查看本部门折旧报表
- 报表查看：查看本部门资产统计报表

### MANAGER权限

- 用户管理：查看本部门用户
- 资产管理：增删改查本部门资产，更新本部门资产状态
- 申请管理：审批本部门领用、调拨、维修申请，处理报废申请初审和最终确认
- 盘点管理：创建和管理本部门盘点计划，分配盘点任务
- 折旧管理：计算本部门资产折旧
- 采购管理：管理本部门采购申请和订单
- 报表查看：查看本部门资产统计报表

### USER权限

- 用户管理：查看个人信息
- 资产管理：查看个人名下资产，查看资产信息
- 申请管理：提交领用、调拨、维修、报废申请
- 盘点管理：执行分配给自己的盘点任务
- 报表查看：查看个人资产统计

## 数据隔离规则

### 资产数据隔离

- ADMIN：查看所有资产
- LEADER：查看本部门资产（根据dept_id匹配）
- MANAGER：查看本部门资产（根据dept_id匹配）
- USER：查看个人名下资产（根据user_id匹配）

### 申请数据隔离

- ADMIN：查看所有申请
- LEADER：查看本部门申请（根据department_id匹配）
- MANAGER：查看本部门申请（根据department_id匹配）
- USER：查看自己提交的申请（根据applicant_id匹配）

### 报表数据隔离

- ADMIN：查看所有报表数据
- LEADER：查看本部门报表数据
- MANAGER：查看本部门报表数据
- USER：查看个人资产统计数据

## RBAC表关联关系

### user表

存储用户信息，关键字段：

- id：用户ID
- username：用户名（唯一）
- password：密码（BCrypt加密）
- real_name：真实姓名
- dept_id：所属部门ID
- status：用户状态（1启用，0禁用）

### role表

存储角色信息，关键字段：

- id：角色ID
- name：角色名称（唯一）
- code：角色代码（唯一）
- description：角色描述
- status：角色状态

### user_role表

用户角色关联表，实现用户与角色的多对多关系，关键字段：

- id：关联ID
- user_id：用户ID
- role_id：角色ID

### permission表

存储权限信息，关键字段：

- id：权限ID
- name：权限名称
- code：权限代码
- url：权限对应的URL

### role_permission表

角色权限关联表，实现角色与权限的多对多关系，关键字段：

- role_id：角色ID
- permission_id：权限ID

## 权限判断方式

系统通过SecurityContext获取当前用户的UserDTO对象，从中提取roleCodes列表进行权限判断。

角色判断规则：

- 检查roleCodes列表中是否包含指定角色代码
- 角色代码比较不区分大小写
- 支持多种角色格式（ADMIN、admin、ROLE_ADMIN）

权限判断工具方法：

- isAdmin：检查是否为管理员
- isLeader：检查是否为领导
- isManager：检查是否为资产管理员
- hasRole：检查是否拥有指定角色
- hasAnyRole：检查是否拥有任意一个指定角色

## 数据权限过滤实现

资产查询时的数据权限过滤逻辑：

1. 获取当前用户信息
2. 判断用户角色
3. 根据角色应用不同的数据过滤条件
4. ADMIN返回所有数据
5. LEADER/MANAGER返回本部门数据
6. USER返回个人数据

申请查询时的数据权限过滤逻辑：

1. 获取当前用户信息
2. 判断用户角色
3. 根据角色应用不同的数据过滤条件
4. ADMIN返回所有申请
5. LEADER/MANAGER返回本部门申请
6. USER返回自己提交的申请

## 认证流程

前端登录获取JWT令牌，后续请求携带Authorization头。

后端JwtRequestFilter解析令牌，调用Feign远程调用auth服务的validate-token接口验证令牌有效性。

验证通过后，将UserDTO对象存入SecurityContext，供后续权限判断使用。

## 密码安全

用户密码使用BCrypt算法加密存储，确保密码安全性。

登录时系统验证用户输入的密码与存储的加密密码是否匹配。
